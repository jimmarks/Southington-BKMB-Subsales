# Release Notes: v2.0.0.26 - Location-Agnostic Address Matching

**Release Date:** December 3, 2024  
**Previous Version:** v2.0.0.25  
**Type:** Major Refactor - Portability Enhancement

---

## 🎯 Executive Summary

Version 2.0.0.26 removes all hardcoded location-specific logic from the Overpass matching system, making it fully portable to any city/state. The system now uses dynamic ZIP code configuration and Google Maps API geocoding instead of hardcoded Southington, CT coordinates.

**Key Achievement:** System is now location-agnostic and can be deployed anywhere with just ZIP code configuration.

---

## 🚨 Breaking Changes

### None - Fully Backward Compatible

- Existing Southington installations continue working with default ZIPs (06479, 06489, 06467)
- Falls back to old `subsales_served_zips` option if new format not found
- Gracefully degrades when Google Maps API key is unavailable

---

## ✨ What's New

### 1. Dynamic ZIP Code Configuration

**New Settings Panel: "Service Area"**
- User-friendly interface for configuring served ZIP codes
- Supports comma-separated or line-separated input (e.g., `06479, 06489, 06467`)
- Real-time validation for 5-digit ZIP codes
- Visual status indicators showing currently configured ZIPs
- Prominent warning if no ZIPs configured

**Location:**
- `BKMB Subsales` → `Settings` → `Service Area` tab
- Also accessible in `Address Extracts` page (existing UI)

**Storage:**
- Primary: `subsales_served_zipcodes` (array format)
- Fallback: `subsales_served_zips` (comma-separated string)
- Default: `['06479', '06489', '06467']` (Southington, CT)

### 2. Google Maps API Integration

**Dynamic Geocoding:**
- Calculates bounding boxes for configured ZIPs using Google Maps Geocoding API
- Reverse geocodes coordinates to assign accurate ZIP codes
- Replaces all hardcoded latitude/longitude logic

**Caching Strategy:**
- Bounding box cached for 7 days using WordPress transients
- Cache key: `subsales_bbox_<md5(zip_list)>`
- Automatically invalidates when ZIPs change
- Minimizes API costs (~$0.005 per geocode)

**Status Indicators:**
- Green checkmark: API key configured, dynamic geocoding enabled
- Red warning: No API key, using fallback logic
- Located in Settings → Service Area tab

### 3. Refactored Overpass Matcher

**File:** `wordpress-plugin/includes/overpass-matcher.php`

**Removed Hardcoded Elements:**
```php
// REMOVED:
const SOUTHINGTON_BBOX = [41.56, -72.92, 41.63, -72.84];

// Hardcoded ZIP guessing:
if ( $lat > 41.60 ) return '06489';  // Plantsville
if ( $lat < 41.575 ) return '06467'; // Marion
return '06479'; // Main Southington

// Hardcoded city in queries:
node["addr:city"="Southington"]
```

**New Dynamic Methods:**

#### `get_served_zipcodes()`
Retrieves configured ZIPs with multi-level fallback:
1. New option: `subsales_served_zipcodes` (array)
2. Old option: `subsales_served_zips` (string)
3. Default: `['06479', '06489', '06467']`

#### `get_bounding_box()`
Geocodes ZIP boundaries using Google Maps API:
- Queries Google Maps Geocoding API for each ZIP
- Calculates min/max lat/lng from all ZIP bounds
- Returns: `[min_lat, min_lng, max_lat, max_lng]`
- Caches result for 7 days
- Returns `null` if API unavailable (uses fallback logic)

#### `guess_zip_from_coordinates( $lat, $lng )`
Reverse geocodes coordinates to ZIP:
- Uses Google Maps Reverse Geocoding API
- Extracts `postal_code` from response
- Verifies ZIP is in configured served ZIPs list
- Fallback: Returns first configured ZIP
- No longer depends on hardcoded latitude thresholds

**City-Agnostic Overpass Queries:**
```php
// OLD (city-specific):
node["addr:city"="Southington"]["addr:street"="%s"](bbox);

// NEW (city-agnostic):
node["addr:street"="%s"](bbox);
```

## 🔧 Technical Details

### Database Schema Changes
**None** - This release only changes logic, not database structure.

### API Integration

**Google Maps API Endpoints Used:**
1. **Geocoding API** - ZIP boundary calculation
   ```
   GET https://maps.googleapis.com/maps/api/geocode/json?address={zip}&key={api_key}
   ```
   
2. **Reverse Geocoding API** - Coordinate to ZIP conversion
   ```
   GET https://maps.googleapis.com/maps/api/geocode/json?latlng={lat},{lng}&key={api_key}&result_type=postal_code
   ```

**API Requirements:**
- Existing Google Maps API key (already used for mobile app)
- Enable Geocoding API in Google Cloud Console
- No additional cost (within free tier for typical usage)

**Caching Strategy:**
- Bounding box: 7 days (WordPress transient)
- Individual ZIP geocodes: Permanent (only recalculated when ZIPs change)
- Reverse geocodes: Not cached (too variable)

### Fallback Logic

**When Google Maps API is unavailable:**
1. `get_bounding_box()` returns `null`
2. Overpass queries use entire configured ZIP list (less efficient)
3. `guess_zip_from_coordinates()` returns first configured ZIP
4. Warning displayed in admin UI

**Migration Path:**
- Existing installations: No action required (defaults to Southington)
- New deployments: Configure ZIPs in Settings → Service Area
- Multi-location: Add all served ZIPs to configuration

## 📊 Performance Impact

### Positive Changes
- **Reduced Overpass queries:** Bounding box limits geographic search area
- **Efficient caching:** 7-day cache prevents repeated API calls
- **Batch processing:** Multiple ZIPs geocoded together, results cached

### API Costs
- **Geocoding (ZIP to bounds):** ~$0.005 per ZIP, cached 7 days
  - Example: 3 ZIPs = $0.015 every 7 days = ~$0.078/month
- **Reverse Geocoding (coords to ZIP):** ~$0.005 per address match
  - Only called when address lacks ZIP code
  - Typical: 10-20 addresses per shapefile upload
  - Example: 20 addresses = $0.10 per upload

**Monthly Cost Estimate:** $1-5 for typical usage (well within Google's $200 free tier)

## 📚 User Documentation

### How to Configure Service Area

**Step 1: Access Settings**
1. Navigate to `BKMB Subsales` in WordPress admin menu
2. Click on `Settings` tab
3. Select `Service Area` panel

**Step 2: Enter ZIP Codes**
1. In the "Served ZIP Codes" field, enter your ZIPs:
   - **Comma-separated:** `06479, 06489, 06467`
   - **Line-separated:** (one ZIP per line)
     ```
     06479
     06489
     06467
     ```
2. Click `Save ZIP Codes`

**Step 3: Verify Configuration**
- Check the status box showing "Currently serving X ZIP codes"
- Verify the displayed ZIPs are correct
- Confirm Google Maps API status (green checkmark = active)

**Step 4: Upload Shapefiles**
1. Navigate to `Address Extracts`
2. Upload shapefiles for your configured service area
3. System will automatically use configured ZIPs for matching

### How It Works

**Address Extraction Pipeline:**
```
Shapefile Upload
    ↓
GPS coordinates stored in wp_ss_addresses
    ↓
get_served_zipcodes() reads configured ZIPs
    ↓
get_bounding_box() geocodes ZIPs → bounding box (cached 7 days)
    ↓
Overpass queries OpenStreetMap within bounding box
    ↓
guess_zip_from_coordinates() reverse geocodes → assigns ZIP
    ↓
Verified address with accurate ZIP stored
```

**Key Features:**
- **Dynamic Boundaries:** No hardcoded coordinates - works anywhere
- **Accurate ZIP Assignment:** Uses Google Maps reverse geocoding
- **Efficient Caching:** Minimizes API calls and costs
- **Graceful Fallbacks:** Works even without API key (reduced accuracy)

## 📦 Deployment Instructions

### For Existing Installations (Southington)

**No action required!** The plugin will:
1. Use existing `subsales_served_zips` option (if present)
2. Default to Southington ZIPs (06479, 06489, 06467)
3. Continue working exactly as before

**Optional: Migrate to new format**
1. Navigate to `Settings → Service Area`
2. Verify ZIPs are displayed correctly
3. Click `Save ZIP Codes` to migrate to new format
4. Check for green Google Maps API status

### For New Installations (Other Locations)

**Required steps:**
1. Upload `subsales-management.zip` to WordPress
2. Activate plugin
3. Configure Google Maps API key (`Settings → Overall Settings`)
4. Navigate to `Settings → Service Area`
5. Enter your served ZIP codes
6. Click `Save ZIP Codes`
7. Upload shapefiles for your location
8. Verify addresses match correctly in Address Extracts

### API Key Setup

If you don't have a Google Maps API key:
1. Go to [Google Cloud Console](https://console.cloud.google.com/apis/credentials)
2. Create a new project (or select existing)
3. Enable **Geocoding API** and **Maps JavaScript API**
4. Create credentials → API key
5. Restrict key to your WordPress domain
6. Copy key to `Settings → Overall Settings`

**Cost:** First $200/month free (sufficient for typical usage)
